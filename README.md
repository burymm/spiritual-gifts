# Карта духовных даров

Веб-приложение для оценки духовных даров: инструкция → необязательная анкета
(214 утверждений) → калибровочная мозаика качеств → результат по 22 дарам.

Сейчас работает весь путь профиля, оценка по ссылке-приглашению со средним
результатом 360°, раздел пастора и админка с назначением пасторов. Вход через
Google обязателен: главная страница — это вход,
остальные разделы закрыты, пока сессии нет. Профиль (анкета, веса, источник)
автоматически сохраняется в `back/` на почте вошедшего и восстанавливается на
любом устройстве. На локальной сборке без ключей Google работает эмуляция
входа почтой.

## Что уже работает

- **Инструкция** — объяснение шагов, шкалы и того, что проценты не являются
  вероятностью.
- **Анкета (основное)** — 200 основных + 14 кандидатских утверждений, шкала
  1…5 («Никогда» … «Всегда»), по 20 вопросов на страницу. Это главный шаг:
  веса считает движок по ответам, вручную ничего расставлять не нужно.
- **Диаграмма (прототип)** — полигональная мозаика из шестиугольных клеток
  на пул из 1200 единиц (50 на каждое из 24 качеств): площадь области строго
  пропорциональна весу качества. Веса калибруются ползунками или вводом числа
  вручную, сумма всегда остаётся 1200. Пока это прототип: ручные веса дают
  быстрый набросок, а после правки любого веса результат считается по ним, а
  не по анкете. Для точного результата — заполнить анкету и не менять
  диаграмму; «Сбросить» вернёт веса из анкеты.
- **Результат** — топ-3 дара и полный список 22 даров с процентами; сильная
  зона — от 75%, слабая — ниже 50%; отрицательные значения показываются как 0%.
- **Средний результат** — тумблер над списком, по умолчанию включён: к вашей
  анкете добавляются присланные оценки равными голосами, и показывается средний
  результат всех заполненных профилей (веса нормируются и усредняются, потом
  округляются до пула). Выключён — видны только ваши ответы и веса. Если своя
  анкета не заполнена, в среднее идут только присланные оценки.
- **Автосохранение** — каждое изменение уходит в API с задержкой 800 мс (сначала
  `POST /api/profiles`, дальше `PATCH`), профиль подхватывается при старте; при
  недоступном API интерфейс продолжает работать локально и сохраняет при следующем
  изменении.
- **Приглашения** — на странице результата блок «Пригласить»: почта пастора
  и друга, после её ввода создаётся запись в базе (`POST /api/invitations`) и
  появляется ссылка `/invite/<token>` с кнопкой копирования. Роль и почта
  приглашённого живут в записи, а не в URL; повторный ввод той же почты и роли
  возвращает ту же ссылку. Письма не отправляются: почтового сервера нет,
  ссылку передают вручную. Экран `/invite/<token>` открывается без входа и
  читает роль через публичный `GET /api/invitations/<token>`.
- **Оценка по ссылке** — после входа тот же путь, что и у себя, но про
  пригласившего: `/invite/<token>/survey` → `/invite/<token>/diagram` →
  `/invite/<token>/result`. Ключ приглашения остаётся в адресе, и ссылки в
  шапке ведут только по этим шагам: выйти в свою карту можно по логотипу.
  Состояние оценки отдельное, поэтому ответы не попадают в свой профиль.
  Отправка — кнопкой «Отправить результат» на последнем шаге
  (`POST /api/invitations/<token>/evaluation`, запись в `evaluations`,
  `used_at` в приглашении); только после неё появляется «Перейти в свой
  профиль». Ссылка одноразовая, и это видно: на экране приглашения владелец
  видит список выданных ссылок со статусом «ждём ответа» или «оценка получена»
  с датой; закрытую ссылку скопировать нельзя, и повторно тому же человеку в
  той же роли она не выдаётся. Приглашённый, открывший пройденную ссылку,
  видит «Вы уже прошли — спасибо» и кнопку «Посмотреть отправленную оценку»:
  результат открывается только для чтения и только её автору.
- **Пастор** — раздел `/pastor` виден только назначенным: админ отмечает их
  почты в админке. Пастор видит список людей, которые прислали ему анкету на
  оценку (только своих, не всех), и результат каждого: топ-3 дара и все 22 с
  процентами. Тумблер «Показывать средний результат» (включён по умолчанию)
  добавляет к профилю присланные оценки равными голосами — как на своей
  странице результата. Если назначение сняли, раздел закрывается при
  следующем обновлении — данные аккаунта остаются.
- **Админка** — `/admin` только для администратора: список последних профилей
  всех пользователей с тумблером среднего результата (оценки со всех сторон)
  и управление пасторами — назначить почту и снять роль (`/api/admin/pastors`);
  назначение повторяемо без дублей, удаление — одна запись.
- **Вход** — главная страница и обязательный шаг: настоящий OAuth через Google,
  а на локальной сборке (без ключей Google) — эмуляция входа почтой. Без сессии
  любой раздел перенаправляет на `/login` (гард), API отвечает 401, шапка не
  показывает навигацию. После входа профиль привязан к почте:
  `GET /api/profiles/mine` отдаёт сохранённые результаты, чужие профили
  недоступны (404), а профиль без владельца, оставшийся от прежней версии,
  «забирается» аккаунтом при первом сохранении.

Правила расчёта описаны в `docs/Контекст проекта.md` и
`docs/spiritual_gifts_documentation.md`. Markdown-файлы в `docs/` — источник
истины; при расхождении с DOCX/PDF побеждает Markdown.

## Структура

```
docs/                       требования и методика (Markdown — источник истины)
back/                       Fastify API: сохранение профилей в Postgres/Supabase
tools/generate-data.py      генерация TypeScript-данных из docs/
front/                      Angular 19 приложение
  src/app/core/             модели, конфиг, датасет, движок расчёта
  src/app/core/data/        сгенерированные вопросы, качества, дары, группы
  src/app/features/         instruction, survey, diagram, result, login, invite
  src/app/state/            сигнальные store: свой профиль и оценка по ссылке
  tests/                    vitest-тесты движка, мозаики и store
```

## Запуск

Требуется Node.js 20+ и npm.

```bash
cd front
npm install
npm start          # http://localhost:4200
```

Маршруты: `/` и `/login` — вход, `/instruction`, `/survey`, `/diagram`,
`/result` открываются только после него, `/pastor` — раздел назначенного
пастора, `/admin` — админка, `/invite/<token>` — экран по ссылке
приглашению (без входа), `/invite/<token>/survey`, `/diagram`, `/result` —
шаги оценки пригласившего (вход нужен: почта оценщика берётся из сессии).

### Бэкенд

Сохранение профилей (ответы + веса) — Fastify + Postgres, обычно Supabase.
Подробности, схема и маршруты — в [back/README.md](back/README.md):

```bash
cd back
npm install
cp .env.example .env   # вставить DATABASE_URL из Supabase
npm run dev            # http://localhost:3000/api/health
```

## Проверки

```bash
cd front
npm run test:engine   # vitest: движок, мозаика, store
npm run typecheck     # tsc для приложения и тестов
npm run build         # production-сборка
```

`npm test` (Karma + Jasmine) требует установленного браузера и оставлен для
компонентных тестов Angular; основные проверки идут через vitest.

## Данные

Вопросы, качества, профили даров и группы генерируются из Markdown-источников:

```bash
python tools/generate-data.py
```

Скрипт перезаписывает `front/src/app/core/data/*.data.ts` и
`_snapshot.json`. После правок в `docs/` запускайте его и проверяйте тесты.

## Настройки

`front/src/app/core/config.ts`:

- `INCLUDE_CANDIDATE_QUESTIONS` — включать ли вопросы 201–214 (по умолчанию
  `true`); выключение убирает их и из анкеты, и из ключа качеств;
- `STRONG_THRESHOLD = 75` — порог сильного выражения;
- `WEAK_THRESHOLD = 50` — порог слабой зоны;
- `TOP_N = 3` — сколько даров показывать в топе.

## Статус

Первый рабочий срез завершён: инструкция → анкета → мозаика → результат, всё
на типизированных данных из `docs/`. Код хранится в git (ветка `main`, первый
коммит — «Первый рабочий срез»).

Что осталось на следующие этапы:

- проверить порог 75% и матрицу 22 даров на реальных результатах;
- визуальная приёмка экрана диаграммы на реальных профилях;
- приглашения выдаются и принимают оценку, присланное входит в средний
  результат 360°; раздел пастора пока показывает роль и статус, а кабинет с
  людьми и отправленными оценками — следующий шаг; роли в церкви (кто есть
  кто) ещё не сделаны;
- средний результат считается в браузере из весов: при большом числе оценок
  его стоит перенести на сервер.

Матрица 22 даров и веса качеств — рабочая гипотеза, а не валидированная
методика.
